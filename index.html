BEFORE YOU BEGIN

How the web vault works

Six things to know before storing important information.

01

Start or open a vault

Choose Create New Vault for an empty temporary vault, or Open Existing .pnvault to read a full encrypted backup created on iOS or web. Opening a backup requires the password used when that file was created.

02

Work inside the temporary session

Add, update, copy, or delete passwords in Passwords. Create and edit notes in Notes. Changes are encrypted into temporary browser session storage; this working session is not a permanent backup.

03

Understand Privacy Lock

Switching browser tabs, minimizing, or putting the browser in the background immediately hides the vault and removes readable values from memory. Enter the Master Password again to continue. Privacy Lock does not delete the encrypted working session.

04

Understand session expiry

After the selected period of inactivity, the temporary vault is deleted. The default is 5 minutes and Settings offers 2, 10, 15, or 30 minutes. Activity resets the timer; Privacy Lock and expiry are separate protections.

05

Export before leaving

Use Export Vault to download an encrypted .pnvault containing all passwords and notes. Store it safely before ending the session, clearing site data, or closing the browser. Section exports create .pnpass or .pnnote files.

06

Keep the correct Master Password

An encrypted file has no readable value without the password used to create it. Pass & Note does not store, recover, reset, or reveal this password. Older exports may use an older password.

Do this

  • Export a full .pnvault after important changes.
  • Keep encrypted backups in more than one safe location.
  • Remember which Master Password protects each backup.
  • Use the 2-minute timeout on a shared device.
  • End the session when finished.

Avoid these mistakes

  • Do not treat the temporary browser session as a backup.
  • Do not clear browser data before exporting.
  • Do not lose or forget the Master Password.
  • Do not leave downloaded .txt notes on a shared device.
  • Do not import the same file repeatedly unless duplicates are intended.

About Pass & Note

Privacy, security, help, and legal information for the web vault.

About Us & Your Data ›

Your data stays with you

Pass & Note Web exists to help you open, read, update, and create Pass & Note encrypted files from a web browser. We do not need an account to provide this functionality.

Local vault processing

Your Master Password, decrypted passwords, notes, and encrypted working vault are processed locally by your browser. This version does not intentionally send or save vault contents on a Pass & Note server.

What the website host can see

Like any hosted website, the server or hosting provider may receive normal connection information when loading the page, such as an IP address, request time, browser type, and requested files. That is separate from vault content, which is handled locally.

Our role

We provide the tools that let your browser read compatible encrypted files when you supply the correct password. You remain in control of the files, passwords, backups, and storage locations.

About the App ›

About Pass & Note

Pass & Note is a privacy-focused offline vault for securely storing passwords and personal notes on your device. The web app follows one principle: your vault belongs to you. No Pass & Note account or server is required. Your data is stored in encrypted browser storage, and you decide when to import or export it.

The web vault works with encrypted .pnpass, .pnnote, and .pnvault files created by the iOS app.

How Pass & Note Protects Your Data ›

Local encrypted storage

Passwords and secure notes are encrypted before being placed in this browser's local storage. Encryption and decryption take place on your device using the browser Web Crypto API.

Master Password

Your raw Master Password is not stored. It is used to derive the cryptographic key needed to open your vault. Pass & Note cannot recover or reveal it.

App privacy

Lock the vault before leaving a shared device. Unlike a native app, a website cannot fully control browser screenshots, extensions, clipboard history, malware, or operating-system previews.

Encrypted backups

Exports use AES-256-GCM with a key derived using PBKDF2-HMAC-SHA256. The password active when a file is created is required to decrypt it.

Security limitations

No software guarantees absolute protection. Security may be reduced on a compromised device, by malicious browser extensions, while the vault is unlocked, or when another person obtains your password or exported files.

Master Password & Recovery ›

Master Password

Your Master Password is the primary credential protecting the web vault. It cannot be recovered. If you forget it, locally encrypted data may become permanently inaccessible.

Browser data

Clearing site data, using private browsing, changing browser profiles, or uninstalling the browser may remove the local vault. Keep an encrypted .pnvault backup somewhere safe.

Previous exports

Changing a vault password does not change the password on earlier backup files. Each file continues to require the password used when it was created.

Export & Import Guide ›

.pnpass

An encrypted package containing one or more password records.

.pnnote

An encrypted package containing one or more secure notes.

.pnvault

A complete encrypted backup containing passwords and secure notes. Use this for backup or moving data between web and iOS.

.txt

A readable, unencrypted single note. Anyone with the file can read it.

Importing data

Imported records are added to the current vault; existing records are not deleted. Importing the same file more than once can create duplicates. The backup password can differ from the current vault password.
